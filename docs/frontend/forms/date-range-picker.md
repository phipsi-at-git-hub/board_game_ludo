# Date Range Picker

## Overview

The `Date Range Picker` is a progressive UI enhancement for HTML `input`
elements using:

``` html
data-ui="date-range"
```

The original input remains the technical form field and is changed
internally to `type="hidden"` during initialization. The visible user
interface is generated dynamically by JavaScript.

The picker supports:

- date range selection
- optional start and end time selection
- German and English localization
- month navigation
- highlighting of the current day
- highlighting of range start, end, and intermediate days
- optional reset functionality
- a `Today` quick action
- explicit `Apply` confirmation when time selection is enabled
- initialization from an existing input value
- native `change` events on the original input
- automatic closing when clicking outside the picker

The implementation is located at:

``` text
public/js/forms/date_range_picker.js
```

This documentation describes the public behavior and configuration of
the picker. Internal implementation details may change without requiring
changes to its HTML usage.

------------------------------------------------------------------------

# 1. Basic Usage

A basic date range picker is enabled through an input element:

``` html
<input
    type="text"
    data-ui="date-range"
    name="date_range"
>
```

After initialization, the input is internally changed to
`type="hidden"`. The user then interacts with the visible picker UI
generated by the JavaScript implementation.

The value of the original input uses the internal format:

``` text
yyyy-mm-dd hh:mm:ss - yyyy-mm-dd hh:mm:ss
```

Example:

``` text
2026-09-01 00:00:00 - 2026-09-17 23:59:59
```

The internal format is independent of the UI localization.

------------------------------------------------------------------------

# 2. HTML Configuration

The picker is configured through `data-ui-*` attributes.

## `data-ui`

Required attribute used to enable the picker:

``` html
data-ui="date-range"
```

Inputs without this attribute are ignored by the date range picker.

------------------------------------------------------------------------

## `data-ui-localization`

Defines the language and locale used by the visible UI.

### German

``` html
data-ui-localization="de"
```

or, for example:

``` html
data-ui-localization="de-DE"
```

The implementation recognizes values beginning with `de` as German
localization.

Internally, the locale used is:

``` text
de-DE
```

### English

All other values are treated as English. The default locale is:

``` text
en-US
```

Example:

``` html
data-ui-localization="en-US"
```

### Default

If no localization attribute is specified:

``` html
<input
    data-ui="date-range"
>
```

the English UI is used.

------------------------------------------------------------------------

## `data-ui-with-time`

Enables start and end time selection.

### Without time

``` html
<input
    data-ui="date-range"
    data-ui-with-time="false"
>
```

This is also the default behavior.

### With time

``` html
<input
    data-ui="date-range"
    data-ui-with-time="true"
>
```

When time selection is enabled, two additional time fields are
displayed:

- start time
- end time

The `Apply` button is also displayed.

Times can be entered manually using the `HH:MM` format or selected from
a predefined list.

The predefined time values are generated in 30-minute increments:

``` text
00:00
00:30
01:00
01:30
...
23:00
23:30
```

The final option is explicitly added as:

``` text
23:59
```

------------------------------------------------------------------------

## `data-ui-with-reset`

Enables the reset action.

``` html
<input
    data-ui="date-range"
    data-ui-with-reset="true"
>
```

The reset button is only created when the value is exactly:

``` text
true
```

Example with reset:

``` html
<input
    data-ui="date-range"
    data-ui-with-reset="true"
>
```

Without reset:

``` html
<input
    data-ui="date-range"
    data-ui-with-reset="false"
>
```

or simply:

``` html
<input
    data-ui="date-range"
>
```

### Purpose

The reset action is particularly useful when the consuming API supports
an empty date range as a valid state.

When reset is triggered:

``` js
input.value = '';
```

is set and a `change` event is dispatched.

``` text
    │
    └── .date-range-actions
        ├── .date-range-actions-left
```

The actions are intentionally divided into a left and a right flex

The left side contains the direct selection actions:

``` text

```

``` text

```

This structure keeps the layout generic and allows additional actions to
be added to either side without changing the overall structure.

# 5. Date Range Selection

The picker maintains two primary internal values:

``` js
rangeStart
rangeEnd
```

In addition, it uses:

``` js
selectingRange
```

to determine whether the user is currently selecting the start or end
date.

## First selection

On the first click, the selected date becomes the start date:

``` text
rangeStart = selectedDate
rangeEnd   = null
```

The picker then asks the user to select the end date.

Example:

``` text
01.09.2026
```

results in:

``` text
Pick end date
```

------------------------------------------------------------------------

## Second selection

On the second click, the selected date becomes the end date.

If a date before the start date is selected, the two dates are
automatically ordered.

Example:

``` text
Selection:
10.09.2026
05.09.2026
```

results in:

``` text
05.09.2026 - 10.09.2026
```

A range with identical start and end dates is valid.

------------------------------------------------------------------------

# 6. Behavior Without Time Selection

When `data-ui-with-time` is not enabled, the range is applied
immediately after the second date is selected.

The selected dates are normalized to the full day.

The start becomes:

``` text
00:00:00
```

The end becomes:

``` text
23:59:59
```

Example:

``` text
01.09.2026 - 10.09.2026
```

is stored as:

``` text
2026-09-01 00:00:00 - 2026-09-10 23:59:59
```

After successful application, the dropdown is closed.

------------------------------------------------------------------------

# 7. Behavior With Time Selection

When:

``` html
data-ui-with-time="true"
```

is enabled, the range is not applied immediately after the second date
selection.

Instead, start and end time fields are displayed.

After a date range has been selected, default times are assigned if no
times have been specified yet:

``` text
Start time: 00:00
End time:   23:59
```

The user can then adjust these values.

The range is written to the original input only after clicking:

``` text
Apply
```

------------------------------------------------------------------------

# 8. Time Validation

Valid manually entered times use the format:

``` text
HH:MM
```

with a valid range of:

``` text
00:00 - 23:59
```

Examples of valid values:

``` text
00:00
08:30
12:00
23:59
```

Examples of invalid values:

``` text
8:30
24:00
12:60
abc
```

Invalid values result in an error status and prevent the range from
being applied.

------------------------------------------------------------------------

# 9. Chronological Validation

A date range must always be chronologically valid.

This is especially important when start and end are on the same day.

Example:

``` text
17.09.2026 18:00 - 17.09.2026 10:00
```

is invalid.

This is valid:

``` text
17.09.2026 10:00 - 17.09.2026 18:00
```

For multi-day ranges, the complete start and end timestamps are
compared.

The end timestamp must not be earlier than the start timestamp.

------------------------------------------------------------------------

# 10. Today Action

The picker provides one date shortcut regardless of whether time
selection is enabled:

``` text
Today
```

There is intentionally no separate `Now` action.

The reason is the semantics of a date range picker: `Today` represents
the current calendar day as a range rather than a single point in time.

The action selects:

``` text
today 00:00 - today 23:59:59
```

With time selection enabled, the corresponding time fields are also set
to represent the full current day.

Without time selection, the selection is immediately applied.

With time selection enabled, the user can still adjust the times before
clicking `Apply`.

------------------------------------------------------------------------

## 10.1 Today Button State

The `Today` button is disabled when the current selection already
represents exactly today as a complete range.

For example, on September 17, 2026:

``` text
17.09.2026 - 17.09.2026
```

results in:

``` text
Today: disabled
```

If no selection exists, the `Today` button remains enabled.

This allows:

``` text
no selection
      ↓
    Today
      ↓
today's date
```

The button also remains enabled while only a start date has been
selected.

------------------------------------------------------------------------

# 11. Reset Action

The reset action exists only when:

``` html
data-ui-with-reset="true"
```

is configured.

The reset button is enabled only when a complete date range exists.

For example:

``` text
01.09.2026 - 10.09.2026
```

makes the reset button active.

With no selection:

``` text
Reset: disabled
```

A partially selected range also keeps Reset disabled.

------------------------------------------------------------------------

## 11.1 Reset Behavior

Reset clears all relevant internal values:

``` js
rangeStart = null
rangeEnd = null
selectingRange = false
```

When time selection is enabled, it also clears:

``` js
startTime = null
endTime = null
```

and the visible time fields.

The original input receives:

``` text
''
```

A native `change` event is then dispatched.

The picker remains open so that a new selection can be made immediately.

------------------------------------------------------------------------

# 12. Apply Action

The `Apply` button is displayed only when time selection is enabled.

Without time selection, the range is complete after the second date
selection and is applied immediately.

With time selection, the user may still configure the times after
selecting the dates, so explicit confirmation is required.

------------------------------------------------------------------------

## 12.1 Apply Button State

The button is enabled when:

- a complete date range exists, and
- both times are valid

It is also enabled when:

- no date range exists
- `data-ui-with-reset="true"` is enabled

This allows an explicitly empty date range to be submitted.

A partially selected range cannot be applied.

------------------------------------------------------------------------

# 13. Applying an Empty Range

When reset is enabled, an empty range can explicitly be applied.

Example:

``` html
<input
    data-ui="date-range"
    data-ui-with-time="true"
    data-ui-with-reset="true"
>
```

With no selection:

``` text
rangeStart = null
rangeEnd   = null
```

the `Apply` button is enabled.

Clicking `Apply` leaves the input empty:

``` text
input.value === ''
```

and dispatches a `change` event.

This supports APIs that treat an empty date range as a valid filter
state.

A partially selected range remains invalid:

``` text
rangeStart exists
rangeEnd does not exist
```

------------------------------------------------------------------------

# 14. Input Value

The date range picker uses a fixed internal date format:

``` text
yyyy-mm-dd hh:mm:ss - yyyy-mm-dd hh:mm:ss
```

Example:

``` text
2026-09-01 00:00:00 - 2026-09-17 23:59:59
```

This format is independent of:

- localization
- display format
- calendar language

The UI may display:

``` text
01.09.2026 00:00:00 - 17.09.2026 23:59:59
```

while the actual input value remains:

``` text
2026-09-01 00:00:00 - 2026-09-17 23:59:59
```

This provides a stable format for backend processing.

------------------------------------------------------------------------

# 15. Pre-populated Values

The picker can be initialized with an existing input value.

Example:

``` html
<input
    data-ui="date-range"
    value="2026-09-01 00:00:00 - 2026-09-17 23:59:59"
>
```

During initialization, the value is parsed.

If valid, the corresponding values are assigned to:

``` js
rangeStart
rangeEnd
```

The calendar is then displayed at the month containing the start date.

When time selection is enabled, the existing hours and minutes are also
loaded into the time fields.

Invalid or unparsable values are not treated as an existing range.

------------------------------------------------------------------------

# 16. Calendar

The calendar uses a Monday-to-Sunday week.

German:

``` text
Mo Di Mi Do Fr Sa So
```

English:

``` text
Mo Tu We Th Fr Sa Su
```

The month title is localized using `Intl.DateTimeFormat`.

Month navigation is provided through:

``` text
‹
›
```

for previous and next month.

------------------------------------------------------------------------

Calendar day buttons may receive several state classes.

## `today`

Marks the current day.

``` css
.date-range-calendar-day.today
```

## `range-start`

Marks the selected start date.

``` css
.date-range-calendar-day.range-start
```

## `range-end`

Marks the selected end date.

``` css
.date-range-calendar-day.range-end
```

## `in-range`

Marks days between the selected start and end dates.

``` css
.date-range-calendar-day.in-range
```

## `other-month`

Marks days displayed from the previous or next month to complete the
calendar grid.

``` css
.date-range-calendar-day.other-month
```

A day can have multiple state classes at the same time.

For example, today may also be the range start.

# 20. Opening and Closing

When opened, the picker wrapper receives:

``` css
.open
```

and the trigger receives:

``` css
.active
```

When closed, both states are removed.

Clicking outside an open picker closes it automatically.

Time dropdowns are also closed when clicking outside their respective
time field groups.

The global outside-click handler is registered only once per document.
This is controlled through the body dataset:

``` text
data-date-range-outside-click
```

------------------------------------------------------------------------

# 21. Events

The date range picker uses the native:

``` js
change
```

event on the original input.

A `change` event is dispatched when a range is successfully applied or
reset.

Example:

``` js
document.querySelector('[data-ui="date-range"]')
    .addEventListener('change', event => {
        console.log(event.target.value);
    });
```

A successful selection may produce:

``` text
2026-09-01 00:00:00 - 2026-09-17 23:59:59
```

A reset or explicit application of an empty range produces:

``` text
''
```

The event uses:

``` js
{
    bubbles: true
}
```

so it can also be handled by parent elements or form-related event
delegation.

------------------------------------------------------------------------

# 22. Initialization

The central initialization function is:

``` js
initDateRangePickers()
```

It searches for:

``` css
input[data-ui="date-range"]
```

and initializes every element that has not already been enhanced.

An initialized input receives the class:

``` text
date-range-enhanced
```

This allows `initDateRangePickers()` to be called multiple times without
creating duplicate picker instances.

------------------------------------------------------------------------

# 23. Initialization Flow

The initialization can be summarized as:

``` text
initDateRangePickers()
        │
        ▼
find input[data-ui="date-range"]
        │
        ▼
already initialized?
   ┌────┴────┐
  yes        no
  │           │
  └─ skip     ▼
        read configuration
              │
              ▼
        create visible UI
              │
              ▼
        parse existing value
              │
              ▼
        initialize state
              │
              ▼
        render calendar
```

# 24. Internal State

The picker maintains several internal state values.

## Calendar

``` js
displayedMonth
```

The month currently displayed.

## Range

``` js
rangeStart
rangeEnd
```

The currently selected start and end dates.

## Selection mode

``` js
selectingRange
```

Indicates whether the picker is currently waiting for an end date.

## Times

When `withTime` is enabled:

``` js
startTime
endTime
```

These values are maintained as `HH:MM` strings.

------------------------------------------------------------------------

# 25. Important Internal Functions

The implementation separates its main responsibilities into dedicated
functions.

## `parseInputRange()`

Parses the existing input value.

Expected format:

``` text
yyyy-mm-dd hh:mm:ss - yyyy-mm-dd hh:mm:ss
```

Returns:

``` js
{
    start,
    end
}
```

or:

``` js
null
```

------------------------------------------------------------------------

## `formatInternalDate()`

Creates the technical input format:

``` text
yyyy-mm-dd hh:mm:ss
```

------------------------------------------------------------------------

## `formatDisplayDate()`

Creates the visible date representation according to the selected
locale.

------------------------------------------------------------------------

## `updateTrigger()`

Updates the label of the visible trigger button.

------------------------------------------------------------------------

## `updateStatus()`

Updates the status area below the calendar.

Examples:

``` text
Pick start date
Pick end date
Date range selected
```

With time selection:

``` text
Select start and end time
Invalid time
```

------------------------------------------------------------------------

## `updateTimeState()`

Synchronizes the visible time fields with the internal state and updates
the status and Apply state.

------------------------------------------------------------------------

## `updateApplyState()`

Determines whether the Apply button can be enabled.

It considers:

- whether a complete range exists
- whether both times are valid
- whether an empty range is explicitly allowed through `withReset`

------------------------------------------------------------------------

## `updateActionState()`

Updates the state of the action buttons.

Reset is enabled only when a complete range exists.

Today is disabled when the current selection already represents exactly
today.

------------------------------------------------------------------------

## `applyRange()`

Validates and writes the current range to the original input.

On successful application:

1.  the input value is written
2.  a `change` event is dispatched
3.  the status is updated
4.  the function returns success

An explicitly permitted empty range is handled as well.

------------------------------------------------------------------------

## `renderCalendar()`

Rebuilds the current calendar grid and assigns the appropriate state
classes and click handlers to each day.

------------------------------------------------------------------------

# 26. Time Dropdowns

When `withTime` is enabled, each time field has its own dropdown.

The fields support:

- direct input
- selection of predefined times
- opening and closing the dropdown
- validation

Opening one time dropdown closes the other.

This ensures that only one time dropdown can be open at a time.

------------------------------------------------------------------------

# 27. Reset and API Behavior

`data-ui-with-reset="true"` should only be used when the consuming
application or API supports an empty date range as a valid state.

Example:

``` html
<input
    data-ui="date-range"
    data-ui-with-reset="true"
    name="created_at"
>
```

After reset, the application receives:

``` text
created_at = ""
```

The server-side implementation must handle this state accordingly.

The picker itself does not treat an empty value as an error.

------------------------------------------------------------------------

# 28. Usage Recommendations

## Enable Reset only when an empty range is valid

Use:

``` html
data-ui-with-reset="true"
```

only when the date range is optional.

For required date ranges, Reset should not be offered.

------------------------------------------------------------------------

## Use `withTime` only when time is relevant

A date-only filter should preferably be used without time selection.

``` html
data-ui-with-time="false"
```

is sufficient for that use case.

------------------------------------------------------------------------

## Do not depend on the display format in the backend

The application should always process the technical input value:

``` text
yyyy-mm-dd hh:mm:ss - yyyy-mm-dd hh:mm:ss
```

rather than the visible trigger text.

------------------------------------------------------------------------

# 31. Behavior Overview

``` text
                         Date Range Picker
                                │
                  ┌─────────────┴─────────────┐
                  │                           │
                Date                     Date + Time
                  │                           │
           Select start date          Select start date
                  │                           │

                  │                           │
                  │                    Configure times
                  │                           │
```

# 34. Summary

The Date Range Picker deliberately separates:

- the technical value of the original input
- the visible representation
- the internal selection state
- optional time configuration
- explicit application
- reset
- the `Today` shortcut

The central semantic distinction is:

> A date is selected, a date range is formed, and—when time selection is
> enabled—the range is explicitly applied afterward.

The public configuration remains limited to a small set of `data-ui-*`
attributes:

``` html
data-ui="date-range"
data-ui-localization="..."
data-ui-with-time="true|false"
data-ui-with-reset="true|false"
```

This allows the same picker to be used for simple date filters as well
as optional, time-precise date range filters.
